nmmp 加固与 unmmp 还原原理

nmmp 把 DEX 中的方法改为 native 方法，由本地虚拟机执行。unmmp 模拟这些本地库，读取方法数据，识别指令，再还原为 DEX 字节码。

01

加固后，方法放在哪里

原来的方法体保存在 DEX 中。nmmp 加固时，会把选中的方法改为 native 声明，将字节码、异常表和符号信息放到本地库，再生成对应的虚拟机解释器。

nmmp 还会改写 opcode（指令编号）和符号引用索引。生成的解释器使用同一套编号规则，因此仍能执行这些指令。

02

unmmp 怎么恢复方法

unmmp 使用 Unicorn 模拟 APK 中的本地库。它执行恢复所需的入口和受控指令，直接取得目标库中的数据。

加固 APK→模拟与识别→smali→DEX
1

确认方法绑定

执行 JNI_OnLoad 和注册函数，拦截 RegisterNatives，核对类名、方法名与签名。

取得方法对应的本地入口
2

读取方法数据

运行本地入口，在进入 vmInterpret 时停下，读取字节码、异常表和寄存器布局。

取得指令与参数位置
3

识别指令含义

让解释器执行专门构造的指令，观察寄存器变化、跳转和 JNI 调用。

取得opcode 映射
4

恢复符号引用

调用目标库的 resolver，把索引解析成字段、方法、类型和字符串引用。

取得实际的符号引用
5

写回并校验 DEX

结合方法声明和寄存器类型生成 smali，写回方法体、移除 native 标记，再组装和校验。

输出恢复的 DEX 与 smali

每个 resolver 的引用池分别保存。指令探测执行到下一次调度或返回；无法确认的语义会报错。

03

通过结果判断指令

给未知指令不同输入，比较它的输出与已知运算的结果。下面假设 0x37 执行加法；编号与数据仅作示意。

待识别的编号：0x37比较加法与异或两种候选
输入目标输出加法异或
2, 1333
3, 1442

两种运算都得到 3，还不能区分。

实际工具使用多组输入，还结合控制流、类型和 JNI 调用继续确认。编译器合并的语义需要额外的类型信息来区分。

04

恢复后得到什么

classes_restored.dex

写回方法体后的 DEX。

patched_smali/

恢复后的 smali 文件。

opcode_mapping.json

该 APK 的指令映射。

官方 DEMO app-release-protect.apk：7987 个方法完整恢复，ARM64、x86_64 输出通过校验和、方法签名及 code_item 检查。

恢复结果是字节码，不能完整还原原始 Java 源码、变量名和注释。工具面向官方 dex2c VM，不支持任意修改的 VM 或 C++ 源码模式。
